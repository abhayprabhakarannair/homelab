# Decisions

Newest last. Each entry: the decision, why, and what was rejected.

1. **No chat-app control plane.** Telegram (and similar) could be blocked in India overnight; the platform must work with infrastructure we own or can replace.
2. **ESP32-S3 with the Arduino core over Rust or ESP-IDF directly.** Mature Wi-Fi, TLS MQTT and OTA; the firmware is small and not performance-bound. Logic lives in plain C++ (`imp/src`) tested on the host with sanitizers; `imp.ino` only wires hardware. (Superseded by decision 20.)
3. **imp is a separate device, not a feature of a server.** It must wake devil when every machine at home is off. A Raspberry Pi was too expensive for this. (Superseded by decision 20.)
4. **MQTT as the single bus, devices self-describe.** UIs and future clients are generic; adding a device needs no UI change.
5. **The bus lives on mephisto, reached through Tailscale.** Home is behind CGNAT and mephisto's public IP is ephemeral, so neither can be addressed directly.
6. **Funnel for the bus, Caddy on the tailnet for web.** The ESP32 cannot run Tailscale, so it needs a public TLS endpoint; Funnel provides one without opening ports on mephisto. Web apps stay tailnet-only: Tailscale acts as the access control, and no public 443 is opened.
7. **Real certificates for private hosts.** Wildcard DNS in Cloudflare pointing at the tailnet IP plus DNS-01, instead of MagicDNS names or self-signed certs. A new app is a role and a `sites` entry.
8. **Ansible + Podman Quadlets on AlmaLinux, everything declarative.** Machines get wiped; nothing may live only on a box. Rejected: Docker Compose, hand configuration, NixOS on the server.
9. **SOPS + age over ansible-vault.** Diffable encrypted YAML, two independent recipients: the homelab SSH key (in 1Password) and an offline age key. No passphrase file to lose.
10. **Four repos, one owner of deployment.** homelab holds every host-specific value and secret; the other repos are generic and publishable. Replaced the old monolithic `pc-control` (torn down 2026-11-19). (Three repos since decision 20.)
11. **Public repos with guardrails** (branch protection, gitleaks hook + CI, push protection, Claude deny rules) rather than private repos; the risk was leaked secrets, which the guardrails address.
12. **imp always sends the magic packet**, even if the target looks online: ping state lags by up to `IMP_OFFLINE_AFTER` intervals. (Superseded by decision 20.)
13. **warden runs unprivileged.** polkit grants power-off, reboot and suspend only; actions have a grace period with `cancel`; inhibitors are bypassed so a desktop app cannot block a remote command.
14. **Console in vanilla JS, no framework.** Small surface, no build-time framework churn; all device data rendered with `textContent`. On the slow home link, load time is dominated by the mqtt.js bundle, so it is versioned, deferred, compressed and cached immutably.
15. **Proposed, not decided (2026-11-20): Cloudflare in front plus an API service.** UI on Cloudflare Pages, `api.iamabhay.fyi` through Cloudflare Tunnel to a new service on mephisto (snapshot, SSE stream, commands, history, audit), Cloudflare Access for login, the bus internal-only except Funnel, the tailnet route kept as a fallback. Reason: the ISP reaches Cloudflare much better than Oracle, and the browser would no longer carry broker credentials or the MQTT library. Rejected: SSR (a live view gains nothing from it). Open questions: Cloudflare-in-front versus tailnet-only; Go (preferred) versus TypeScript/Python. See [roadmap](roadmap.md).
16. **OpenWrt on the router and access point, no controller (2026-11-20).** The Omada controller needs an always-on host (old-devil was down for 53 days), keeps the network's configuration in its database rather than in git, and switches ISPs slowly. OpenWrt config is plain files that homelab templates and diffs like any other host. ISPs are ordered failover with mwan3 (BSNL, then RailWire, then Jio): load balancing put a share of connections on the unreliable link and broke IP-bound sessions, and a single flow gains nothing from it. Rejected: keeping Omada with the controller on devil or mephisto (still a controller, config outside git); link bonding through a VPS (OpenMPTCProuter: survives a switch without dropping connections, but adds latency through Hyderabad and the ER605 is too weak); buying a mini PC to host the controller.
17. **warden on the router, imp kept (2026-11-20).** er605 is wired and always on, so it is the main Wake-on-LAN path and reports ISP status, usage and LAN devices; it runs warden with the `wake`, `wan` and `clients` modules (one tested agent, ~20 MB of 240 MB RAM) under procd as an unprivileged user. imp stays: Wake-on-LAN fails when a machine's NIC loses standby power, and only imp can be wired to the power button. The console sends wakes through whichever waker is online. Rejected: a shell agent with mosquitto clients (~3 MB, but untested shell parsing network input on the internet-facing box, and a second copy of the bus contract); Tailscale on the router (~30–45 MB, and a second path that mephisto already provides); moving the bus or web apps home (mephisto stays reachable when the house is down and costs nothing).
18. **A per-device ISP choice is a preference, never a pin (2026-11-20).** `wan_preferences` (config) and console overrides (runtime) only put an ISP first; the other links stay as fallback in order, an override applies only while its ISP is tracked online, and a reboot clears every override. The goal is that no setting can leave a device offline. Overrides go through one root helper (`wanpref`) that only warden's user may call over ubus, so warden itself stays unprivileged. Only DHCP reservations can be switched (2026-11-21): overrides are kept per address, and another device could lease an unreserved one. Rejected: hard pins per device; letting warden change routing directly; keying overrides by MAC (mwan3 rules match addresses, so every lease change would need a rebuild).
19. **Link re-measured on BSNL alone (2026-11-21).** ~90 Mbit/s down (capped by devil's 100 Mbit/s port), ~60 Mbit/s up, 28 ms to mephisto (direct tailnet path), 19 ms to Cloudflare; the console page loads in 0.1 s and the mqtt.js bundle in 0.25 s. The figures behind decisions 14 and 15 (~1.7 Mbit/s, 150 ms vs 52 ms) came from Omada sending traffic over RailWire. Decision 15's main reason, that Cloudflare is reached much better than Oracle, no longer holds; it stays proposed for its other reasons (no broker credentials in the browser, an API for history and a mobile app).
20. **imp retired (2026-11-21).** Reverses the "imp kept" part of decision 17. er605's warden already sends the wakes and pings devil for its power state, and the power-button wiring that justified imp was never built. Retiring it drops a repo, an MQTT user, a Funnel client and devil's OTA port. Rejected: keeping it idle as a second waker (a second firmware to maintain for a path that has not been needed).
21. **Shape a link with cake only where it bloats (2026-11-21).** sqm-scripts is installed and a WAN is shaped by giving it `sqm` rates (cake, ethernet framing, 44 bytes overhead, MPU 84: the OpenWrt default for fibre when the true overhead is unknown). BSNL is not shaped: measured from devil, latency to 1.1.1.1 rose from ~20 ms idle to 21 ms with the download saturated (88 Mbit/s) and 24 ms with the upload saturated (90 Mbit/s), so cake has nothing to fix, and the 85/54 Mbit/s first configured would have cut the upload by 40 %. RailWire and Jio get shapers only if the same test shows bloat. Rejected: hardware flow offloading (bypasses the shaper).
22. **OpenWrt upgrades through owut (2026-11-21).** `upgrade.yml` asks OpenWrt's build server (ASU) for the current release with current package revisions and everything installed, and sysupgrade keeps the config plus the files the roles list in `/lib/upgrade/keep.d`; a first-boot script turns off the services the roles keep off. Packages are never upgraded with `apk` (each upgrade costs overlay space twice, and eap225 has 5.8 MB). Rejected: a local Image Builder (a package list and build to maintain for what ASU already does; kept as a fallback in Podman if ASU is ever unavailable); reinstalling packages with Ansible after each flash (the device comes up without warden and mwan3 until someone runs it).
23. **DNS ad blocking on the router with OpenWrt's `adblock` package (2026-11-21).** Every LAN device uses er605's dnsmasq, so blocking there covers phones, TVs and apps that a browser extension cannot reach; it complements uBlock Origin, which still handles ads served from the content's own domains (YouTube). The official package is maintained (several releases in Oct 2026), installs from the OpenWrt feed and so survives owut upgrades, keeps the previous list when a download fails, and bridges DNS to 1.1.1.1 while dnsmasq restarts. One list, Hagezi Multi Pro (~245k domains, updated daily, free under GPL-3.0, Hagezi's recommended level); er605 has ~150 MB free. If it breaks sites the allowlist takes them, and Multi Normal (~195k) is the step back. The Jio set-top box is exempt: the list blocks `jioads.jio.com`, `collect.media.jio.com` and `mercury.jio.com`, the ads on the box are mostly in the stream, and live TV is not worth risking. Reversed the same day as a trial, since the box's launcher and apps showed many ads. Jio box owners who block ads by DNS (OnlyTech forum, 2025–26) report JioTV+ ads gone and JioTV+, Hotstar and other apps working, no penalty from Jio, ads inside live streams kept, and some ZEE channels (mostly Hindi) failing because they need `pubads.g.doubleclick.net`, which Pro blocks. Allowlisting it would unblock Google's ad server for every device, so a ZEE failure means choosing between that and the box back in `router_adblock_exempt`. Rejected: adblock-lean (a script installed outside the package feed, one or two maintainers, last release Dec 2025); AdGuard Home (replaces dnsmasq, too big for er605's flash); a blocker on mephisto (LAN devices cannot reach it without Tailscale on the router, decision 17); Technitium on old-devil (being retired).
24. **DNS over HTTPS from the router (2026-11-21).** dnsmasq forwards only to local `https-dns-proxy` instances for Cloudflare and Google, so BSNL, RailWire and Jio neither see nor rewrite the house's lookups; DNS-based site blocks (common on BSNL) stop working, while SNI-based ones (Jio, Airtel) do not, since the site name is still visible when a connection starts. The proxy does not edit the dnsmasq config (`dnsmasq_config_update '-'`, the template owns it) or force LAN DNS (that would override adblock's exemptions, whose DNS goes plain to 1.1.1.1), and its startup check against the package author's domain is off. No plain resolver is kept as a fallback: dnsmasq periodically queries every upstream, so one would leak lookups in normal operation; two proxies under procd respawn are the redundancy. Firefox's canary domain is answered locally so it does not switch to its own DoH and skip the blocklist; iCloud Private Relay's is not, so Apple devices keep the feature. Rejected: DNS over TLS with stubby (port 853 is easier for an ISP to block than 443); a resolver on mephisto (an extra hop to Hyderabad for every lookup).
25. **NUT on devil shuts it down at 30 % (2026-11-21).** devil is the only load on its APC Back-UPS RS 1500G-IN. NUT runs standalone on devil (`usbhid-ups`, `upsd` on 127.0.0.1, `upsmon` as primary); warden's `ups` module reads it with `upsc` and the console shows charge, runtime, load and on-battery events. At 30 % charge or 5 min runtime (overriding the UPS's own 10 %, for margin on an ageing battery) `upsmon` powers devil off and NUT's systemd-shutdown hook tells the UPS to cut its output and restore it when mains returns, so devil boots on its own if its firmware powers on after AC loss. er605 is not on the UPS, so nothing at home could wake devil otherwise. Rejected: apcupsd (APC only, and NUT's `upsc` serves warden as well); only reporting (a long cut would end in a hard power loss).
